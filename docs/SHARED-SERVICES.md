# Shared device services

Firmware consumes `open-horizon-labs/embedded-services` as the pinned `shared/embedded-services` Git submodule. The shared repository is private: access to that dependency is required to initialize the submodule and build or run native checks. The public firmware checkout alone is not a complete build tree. Authorized users can run `git submodule update --init --recursive` after cloning. Dependency source notices and provenance remain in the shared repository; no private host-service code or history is imported into this firmware repository.

The shared components own WiFi provisioning worker/radio/HTTP/captive lifecycle, profile parsing and selection, bounded retry/deadline policy, captive DNS, button gestures, idle/USB decisions, SD accounting, RGB565 conversion and asynchronous file writing, typed media catalogs/timelines, durable listening positions and resumable verified HTTP transfer coordination. Product adapters retain portal HTML, NVS namespace, messages, setup duration, station options, physical controls, shutdown orchestration, diagnostic event rings and reports, receiver protocol and activation rules. The extracted worker retains deferred scans, hidden-network fallback, open setup and phone captive probes. Device setup and sync add no authentication gate.

Canonical firmware keeps its newer health-aware discovery selector: it probes all discovered IPv4 candidates across up to eight services, honors cancellation and tests a saved-address fallback. The optional shared first-result discovery helper does not provide those semantics. Its journaled FAT replacement/recovery also remains local; the generic shared publication helper has no equivalent journal. The exact double-phase/exponential-gain audio converter remains local because the shared integer PCM implementation is not numerically equivalent. These are deliberate behavior boundaries, not parallel copies of a matching shared implementation.

Run firmware checks with `tools/check.sh`, `tools/check_captive.sh`, `tools/check_codecs.sh`, `tools/check_sync.sh`, `tools/check_media.sh` and `tools/render_ui.sh`; source ESP-IDF 5.5.5 before native, receiver and build checks (native model checks use its pinned cJSON source). `tools/build.sh` retains the verified SDK SPI ISR patch step. Host preparation/delivery and its integration suite remain in the private media-prep-service repository, as described in [HOST-SERVICE.md](HOST-SERVICE.md).
